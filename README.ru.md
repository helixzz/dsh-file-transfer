**Скачивайте файлы из sidebar DSH Web, загружайте файлы обратно в workspace и пакуйте целую папку в ZIP — по удалённому соединению, а не только на localhost.**

В DeepSeek Harness есть дерево файлов в sidebar: по нему можно просматривать workspace и открывать файлы на предпросмотр, но в обе стороны он работает только на чтение. Этот plugin добавляет недостающие элементы управления:

| **⬆ Upload** и **🗜 ZIP** в заголовке дерева файлов — отправьте файлы в выбранную папку или заберите её целиком | **⬇ Download** в заголовке предпросмотра — сохраняет открытый файл на вашу машину |

## Зачем это нужно

Если harness запущен на headless-машине, а вы работаете с ним через браузер, вам не хватает двух повседневных вещей:

- **Файл не вытащить.** Ничто в sidebar не выставляет `Content-Disposition`, поэтому просматриваемый отчёт, PDF или изображение нельзя сохранить. В итоге приходится возвращаться на хост и копировать файл руками — `scp`, общий диск, USB-флешка.
- **Файл не закинуть.** Файловый сервис workspace предоставляет `list` / `read` / `readBytes` / `stat` / `changes` — и больше ничего. Пути записи нет, поэтому файл с ноутбука нужно сначала доставить на хост каким-то другим способом, прежде чем агент сможет до него добраться.

Этот plugin намеренно небольшой и остаётся в sidebar: он не изобретает новый файловый браузер, а добавляет действия скачивания и загрузки к тому, которым вы уже пользуетесь.

## Возможности

**⬇ Download**

- Файл отдаётся streaming'ом — байты не лежат в памяти хоста единым буфером.
- Поддержка `HEAD` и одиночного `Range`, поэтому работают докачка и проверка размера (`206 Partial Content`).
- `Content-Disposition: attachment` с `filename*` по RFC 5987, поэтому имена с CJK-символами и эмодзи переживают путь туда и обратно, а не приезжают в виде `%E6%8A%A5...`.
- Корректный content type по расширению, плюс `nosniff` и `no-store`.
- Своего потолка на размер нет.

**⬆ Upload**

- Streaming сырых байтов прямо на диск: без multipart-обёртки, без base64 и без раздувания на 33 %.
- Сначала запись идёт в соседний файл `.dsh-part-*` и только после завершения потока переименовывается на место, поэтому прерванная загрузка никогда не оставит обрезанный файл под настоящим именем.
- Никогда не перезаписывает. Второй `report.pdf` становится `report-1.pdf`.
- Необязательный лимит размера (`maxUploadBytes`): отклоняет слишком большие тела запросов и убирает за собой.
- **Целится в папку, которую вы сейчас видите**, а не только в корень workspace: щёлкните по строке папки (или по файлу, чтобы использовать его родителя) — и кнопка пойдёт следом; чип рядом с ней всегда показывает место назначения.
- **Drag-and-drop: перетащите файлы на дерево.** Бросок на строку папки загружает файл в эту папку, бросок на строку файла использует его родителя, бросок на пустое место — корень. Строка под указателем обводится, пока вы тащите.

**🗜 ZIP-архив папки**

- Один щелчок превращает выбранную папку в единый архив: рекурсивно, CJK-имена сохраняются, пустые каталоги сохраняются, symlink пропускаются.
- Запись идёт потоком с deflate на лету — архив никогда не лежит в памяти хоста одним куском.
- Пишется напрямую по спецификации ZIP (data descriptors плюс флаг UTF-8 в именах), поэтому plugin по-прежнему поставляется без единой runtime-зависимости.
- По умолчанию ограничение в 20 000 файлов и необязательный бюджет в байтах; одна запись больше 4 GiB отклоняется, поскольку ZIP32 не может её выразить.

**Общее**

- Аутентификация через собственный слой Connection в DSH: неаутентифицированный запрос отклоняется с `401` ещё до того, как выполнится ваш обработчик. Никакой возни с CSRF-токенами, никакого отдельного логина.
- Allow-list корней, разрешение через `realpath` и отказ при попытке symlink выйти за разрешённые пределы.
- Привычный конверт ошибки (`{ ok: false, error: { code, message } }`) со стабильными машиночитаемыми кодами.

## Установка

```sh
# from GitHub
dsh plugin --profile web add github:helixzz/dsh-file-transfer

# or from a local checkout
dsh plugin --profile web add /path/to/dsh-file-transfer
```

Пакет объявляет `dsh.bundle.patch`, поэтому `dsh plugin add` сам добавляет его в стек слоёв `dsh.profile.bundles` профиля — править `cordis.patch.yml` вручную не нужно.

Дальше либо перезапустите профиль:

```sh
systemctl --user restart deepseek-harness.service   # or however you run dsh web
```

…либо, если ваш профиль работает с `patchReload: live`, дайте загрузчику подхватить новый bundle и просто обновите страницу. (Именно так этот plugin развёрнут на машине, для которой он писался — перезапуск не нужен.)

Откройте сессию, разверните правый sidebar и выберите вкладку **file**. `⬆ Upload` и `🗜 ZIP` находятся рядом с кнопкой перезагрузки, а чип между ними показывает папку, на которую они будут действовать. Откройте любой файл — `⬇ Download` окажется рядом с элементом «открыть с помощью».

## За обратным прокси

Задайте лимит размера тела запроса, подходящий под ваши загрузки. Для nginx:

```nginx
client_max_body_size 100m;
```

Больше ничего не требуется. Аутентификация здесь не забота прокси: маршруты регистрируются в реестре fetch слоя Connection в DSH, поэтому запрос без валидной сессии вообще не доходит до plugin:

```console
$ curl -o /dev/null -w '%{http_code}\n' \
    'http://127.0.0.1:3900/api/dsh-file-transfer/download?path=/etc/hostname'
401
```

## Конфигурация

Все опции необязательны. Переопределяйте их в собственном слое профиля, а не правьте встроенный patch:

```yaml
- id: file-transfer
  config:
    roots: []              # allow-list of absolute roots; [] means unrestricted
    allowUpload: true
    allowOverwrite: false
    maxUploadBytes: 0      # 0 means no limit
    archiveMaxFiles: 20000
    archiveMaxBytes: 0     # 0 means no limit
    compressionLevel: 6    # 0-9, deflate level used by the ZIP route
```

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `roots` | `[]` | Если список не пуст, каждая цель скачивания, загрузки и архивации должна разрешаться — включая symlink — внутри одного из этих корней. Всё остальное получает `403 outside-roots`. |
| `allowUpload` | `true` | Значение `false` полностью убирает маршрут загрузки (`403 upload-disabled`). |
| `allowOverwrite` | `false` | Когда выключено, существующее имя никогда не заменяется: вместо него берётся свободное `name-N.ext`. |
| `maxUploadBytes` | `0` | Отклоняет более крупные тела с `413 upload-too-large` и удаляет недописанный файл. |
| `archiveMaxFiles` | `20000` | Отказывается архивировать дерево с большим числом записей (`413 archive-too-large`). |
| `archiveMaxBytes` | `0` | Отказывается архивировать дерево, файлы которого превышают этот бюджет; `0` отключает проверку. |
| `compressionLevel` | `6` | Уровень deflate для записей архива; `0` сохраняет без сжатия. |

## HTTP API

Три маршрута, все под `/api/`, все требуют аутентифицированного Connection. Удобно вызывать из терминала, скрипта или агента:

```sh
# download (streams to stdout; add -r 0-1023 for a range)
curl -O -J 'https://host/api/dsh-file-transfer/download?path=/abs/report.pdf'

# upload (raw bytes, no multipart envelope)
curl -X POST -H 'content-type: application/octet-stream' \
  --data-binary @report.pdf \
  'https://host/api/dsh-file-transfer/upload?dir=/abs/dir&name=report.pdf'

# zip a directory (any name; defaults to the directory basename)
curl -OJ 'https://host/api/dsh-file-transfer/archive?path=/abs/reports'
```

Успешная загрузка отвечает:

```json
{ "ok": true, "value": { "path": "/abs/dir/report.pdf", "name": "report.pdf", "bytes": 20481 } }
```

Ошибки используют тот же конверт, что и остальной harness:

```json
{ "ok": false, "error": { "code": "outside-roots", "message": "path is outside the configured roots" } }
```

| Код | Статус | Значение |
| --- | --- | --- |
| `missing-path` | 400 | Нет query-параметра `path` / `dir`. |
| `not-absolute` | 400 | Путь был относительным. |
| `not-a-file` / `not-a-directory` | 400 | Не тот тип записи. |
| `invalid-name` | 400 | Из переданного имени после очистки не осталось ничего пригодного. |
| `not-found` | 404 | Путь не существует. |
| `outside-roots` | 403 | После разрешения путь оказался вне настроенных `roots`. |
| `upload-disabled` | 403 | `allowUpload: false`. |
| `name-exhausted` | 409 | Все 10 000 вариантов имени оказались заняты. |
| `upload-too-large` | 413 | Тело запроса превысило `maxUploadBytes`. |
| `archive-too-large` | 413 | Дерево превысило `archiveMaxFiles` / `archiveMaxBytes`, либо одна запись больше, чем допускает ZIP32. |
| `archive-unreadable` | 413 | Какой-то каталог в дереве не удалось прочитать. |
| `archive-failed` | 500 | Архив не удалось сформировать. |
| `write-failed` | 500 | Хост не смог записать файл. |

## Модель безопасности

- **Аутентификация** приходит из реестра fetch слоя Connection — тот же шов, который использует штатный маршрут `/api/file`. Ни один маршрут недоступен анонимно.
- **Разрешение путей**: каждый путь, пришедший из браузера, проходит через `realpath`, поэтому сегменты `..` и symlink разрешаются *до* проверки `roots`. Symlink, ведущий за пределы разрешённого корня, отклоняется, и это проверяется unit-тестом.
- **Имена файлов** сводятся к одному сегменту пути: `../../etc/passwd` превращается в `passwd` и оказывается внутри выбранного каталога. Проверено сквозным тестом, а не только unit-тестом.
- **Запись** атомарна с точки зрения читателя (`.dsh-part-*`, затем переименование) и никогда не затирает существующий файл, если вы сами об этом не попросили.
- **Архивы** строятся обходом каталога, который пропускает symlink и специальные файлы, поэтому ссылка внутри workspace не может втянуть в скачивание посторонний файл. Обход ограничивается по лимитам ещё до того, как будет отправлен первый байт.

Plugin работает с теми же правами, что и процесс harness. `roots` — тот рычаг, который сужает поверхность доступа, когда harness используется совместно, а `allowUpload: false` полностью отключает путь записи.

## Совместимость

Собран и проверен на `@deepseek-ai/dsh` **0.2.0-rc.2**.

Пакет **намеренно не объявляет `peerDependencies`**. Слишком узкий диапазон peer-зависимостей — ровно то, из-за чего версионный гейт DSH отвергает вполне рабочий plugin:

```console
dsh: installation rejected: Plugin <name> is incompatible with dsh 0.2.0-rc.2:
     peerDependencies {"@deepseek-ai/dsh-client-connection":"^0.1.0"}
```

Этот plugin общается только с сервисом `connection` и встроенными модулями Node. Он также избегает клиентских импортов пакетов, удалённых в 0.2 (например, `@deepseek-ai/dsh-client-runtime`), потому что отсутствующая клиентская зависимость не даёт активироваться всей браузерной половине.

## Разработка

Шага сборки нет. `lib/index.js` (host-половина на ESM) и `lib/client.js` (написанный вручную CJS-бандл для `__ModuleLoader__` Web-оболочки) — это и есть поставляемые артефакты, и оба лежат в репозитории, чтобы установка через `github:` работала без prepare-скрипта.

```sh
node --check lib/index.js && node --check lib/client.js
node --test test/host.test.mjs
```

Unit-тесты вызывают экспортированные обработчики обычными объектами `Request` — поэтому Range, заголовки disposition, очистка имён, проверка корней, поведение при перезаписи, лимиты размера, выход symlink за пределы корней и лимиты архивов проверяются без запуска профиля. Пятнадцать кейсов; ZIP-случаи проверяются через `zipfile.testzip()` из Python, который проходит CRC каждой записи.

У элементов управления деревом нет автоматических браузерных тестов: они читают атрибуты `data-files-entry` / `data-files-path` штатного дерева файлов — поэтому и продолжают работать, даже если внутренности дерева изменятся. Если вы трогаете эту обвязку, проверьте её вручную на настоящем workspace.

## Планы развития

- Множественный выбор: архивировать или скачивать несколько строк сразу.
- Кнопка скачивания на карточках доставленных файлов. Сейчас `deliverables.file.actions` отдаёт внутренний action URL, а не путь в файловой системе, поэтому здесь нужна поддержка на стороне upstream.

## Участие в разработке

Issues и pull request'ы приветствуются. Два момента, о которых стоит знать перед отправкой:

- **Запускайте тесты.** `node --test test/host.test.mjs` должен оставаться зелёным.
- **Следите за синхронностью переводов.** README существует на шести языках, и все они описывают один и тот же plugin; если вы меняете поведение, обновите тот перевод, на котором можете писать, и скажите об этом в PR, а остальные подтянутся.

Пожалуйста, не раздувайте поверхность. Вся ценность этого plugin в том, что он предсказуемо делает несколько вещей поверх штатного файлового браузера DSH, а не в том, чтобы вырасти в IDE.
